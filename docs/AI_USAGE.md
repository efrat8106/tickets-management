# AI Usage Log

Running log of where AI assistants were used during development, and what was reviewed or changed by hand.
This log feeds the "AI usage" section of the README.

Tools: **Claude Code** (agent in VS Code, writes code and docs) and **Claude (chat)** (used by the author as a second
reviewer of plans and outputs).

| # | Area / task | What the AI did | What was reviewed / changed manually |
|---|---|---|---|
| 1 | T-01 Work plan | Claude Code drafted `docs/PLAN.md` from the specification (requirement IDs, tasks, estimates, traceability). | The plan was reviewed with the help of a second AI assistant (Claude chat); the author decided on and directed the changes: `RequestId` = ticket FK with a separate `CorrelationId`; cross-cutting task moved before the first endpoint; test tasks moved right after each feature; total hours corrected; CancellationToken/logging added to acceptance criteria; cache justification + scale-out as deliverables, invalidation after commit; `requests.http` task; deterministic + parallel concurrency tests; RowVersion in body (decided and documented); full build + all tests in final verification; index list marked as hypothesis until measured; this log. |
| 2 | T-02 Tooling | Checked installed versions; proposed .NET 10 instead of .NET 8 (not installed, near end of support). | Confirmed by the author – `dotnet --version` → `10.0.303`. |
| 3 | T-03 Skeleton | Claude Code scaffolded the solution, projects, references, `docker-compose.yml`, DI registration. | Verified build (0 warnings, warnings-as-errors) and container health. Two issues found during verification and fixed: a vulnerable transitive package (`System.Security.Cryptography.Pkcs` 9.0.11 via SqlClient) pinned to a patched version rather than suppressed; Compose failed on the Hebrew folder name, fixed with an explicit project `name`. |
| 4 | T-04 Cross-cutting | Claude Code wrote the correlation-id middleware, global exception handler, Serilog/CORS/Swagger/health setup. | Verified manually against the running API: unknown route → 404 ProblemDetails with `correlationId`; client `X-Correlation-Id` echoed in the response and in the log line; CORS preflight from `http://localhost:4200` allowed; Swagger JSON served; `/health` returns 503 while the database does not exist yet (proves the check really queries the DB). Design points chosen deliberately: client correlation ids are length/charset-validated because they reach logs and the DB; exception details only in Development; client-cancelled requests logged as Information (499), not as errors; EF SQL logging enabled only in Development, without parameter values. |
| 5 | T-06 Data model | Claude Code drafted `docs/DATA_MODEL.md` (types, lengths, enum storage, RowVersion, audit) and the index hypotheses in `docs/PERFORMANCE.md`. | Author required explicit justification for Id type, enum storage, RowVersion and column lengths, and that all indexes be labeled as hypotheses until measured. Notable reasoning checked: string enums would sort Priority alphabetically (High, Low, Medium) – a correctness issue, not just size. |
| 6 | T-07 Entities & migration | Claude Code wrote entities, enums, `ITicketsDbContext`, Fluent configurations, `InitialCreate` migration and Development auto-migration. | Generated migration reviewed line by line against `DATA_MODEL.md` (types, lengths, `rowversion`, CHECK constraints, FK `NO ACTION`). Schema verified directly in SQL Server (`sys.tables`, `sys.indexes`, `sys.check_constraints`). A false "healthy" result was caught this way (issue #8). RCSI behavior discovered and documented. |
| 7 | T-08 Seed | Claude Code wrote the seed command (argument parsing, deterministic generator, `SqlBulkCopy` loader in one transaction). | Verified by running it, not by reading code: 100k rows in ~2 s; second run without `--reset` inserts nothing; `--reset` reproduces identical data (same `CHECKSUM_AGG`); invalid args → message + exit code 1. Data checked in SQL: skewed status/priority/org distributions, 50 orgs, 20 assignees, ~9% unassigned, 2-year range, history consistent with current status, constraints remain trusted (`CheckConstraints` option deliberately used – plain bulk copy would leave CHECK/FK constraints untrusted and hurt query plans). |
| 8 | T-09 Test infrastructure | Claude Code wrote `ApiFixture` (Testcontainers + WebApplicationFactory), the isolation guard, a test-only throwing controller and 3 infrastructure tests. | Author required that tests run on a separate container and never reset the 100k development data. Verified: dev DB count 100,000 before and after `dotnet test`; test container removed after the run; the guard aborts if the API is connected to any other database. Test-only endpoint lives in the test assembly, not in production code. FluentAssertions pinned to 7.2.0 for licensing reasons. |
| 9 | T-10 Query validation | Claude Code wrote `TicketQuery`, the sort-field whitelist, `TicketQueryValidator`, a generic `FluentValidationFilter` (same `ValidationProblemDetails` shape as model-binding errors) and 14 unit tests. | One failing test analyzed (issue #9) and fixed in the test, not by weakening the validator. Checked deliberately: numeric enum values (`status=7`) bind successfully in ASP.NET Core and are therefore rejected by the validator; `sortBy` is a whitelist (SQL-injection-style input covered by a test). |
